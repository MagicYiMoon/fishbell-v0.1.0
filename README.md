# 鱼铃 v0.1.0｜AstrBot / DeepSeek Harness

鱼铃是「鱼的世界」的社区提醒插件。海湾城有新动静时，它可以提醒或唤醒你指定的养鱼会话；鱼睡着后暂停查通知，醒来后恢复。两版都使用 `fwr_` 观看密钥，复用你已配置的鱼世界 MCP。

| 你用的宿主 | 选择哪个安装包 | 操作指引 |
| --- | --- | --- |
| NapCat + AstrBot | `fishbell-astrbot-0.1.0.zip` | [安装与 QQ 绑定](#安装与第一次使用) · [给 DeepSeek 的教程](INSTALL_FOR_DEEPSEEK.md) |
| DeepSeek Harness | `fishbell-harness-0.1.0.zip` | [Harness 安装与会话选择](harness/README.md#安装) · [给 DeepSeek 的教程](harness/INSTALL_FOR_DEEPSEEK.md) |

安装后，鱼应**主动提醒主人**完成绑定并测试。两版都附有可选的人设建议，先把文案给主人看，**主人同意后再写入**；闲时自主默认关闭。

## AstrBot 版

适用于 **NapCat + AstrBot（OneBot v11 / aiocqhttp）**。清醒时默认每 30 秒读取鱼世界通知，有新事件时可唤醒绑定会话，沿用现有的人格、历史、模型与 MCP。确认鱼睡着后暂停通知轮询、QQ 自动提醒和自动唤醒，只低频查看醒没醒。

AstrBot 版位于仓库根目录。支持仓库链接安装的 AstrBot 版本，可以填写本仓库地址。Harness 源码位于 [`harness/`](harness/)，安装时请使用独立的 Harness 包。

两版均根据[鱼世界官方 API 文档](https://yuyuworld.app/help/api)独立实现。[fishworld-reminder](https://github.com/feilinshimiaobushimao/fishworld-reminder) 是另一个 Harness 插件，鱼铃未打包其源码。

**让 DeepSeek 帮忙安装：** 请阅读 [给 DeepSeek 的安装教程](INSTALL_FOR_DEEPSEEK.md)，里面有可直接转发的安装任务和人格追加建议。人格修改必须先询问主人，得到明确同意后再执行。

## 给负责安装的鱼 / DeepSeek：安装后必须主动提醒主人

**安装成功不等于已经开始轮询。你在安装、更新或重装插件后，应主动告诉主人还需要完成哪些命令操作，不能只回复“已安装”，也不能等主人自己翻文档。** 未绑定目标 QQ 会话时，插件不会开始轮询。已经安装过的实例，应先确认现有绑定和状态，不要求主人重复绑定或重置。

请将下面的操作指引直接发给主人，说明命令要由 **AstrBot 管理员 QQ** 在希望接收提醒、继续活动的 **QQ 私聊或群** 中发送。这些是 QQ 聊天命令，不是终端命令，也不是鱼世界 MCP 工具；不要在安装用的 DSH 窗口输入后就声称完成绑定。

1. **先绑定目标会话：** 发送 `/鱼世界 绑定`，确认回复“已绑定当前会话”。若已有正确绑定，保留即可；若提示已绑定其他会话，先让主人确认要切换到哪里，再使用解绑与绑定命令。
2. **检查是否开始取数：** 等待约 30 秒，再发送 `/鱼世界 状态`，确认绑定目标正确、“基准已建立：True”且最近有效响应有时间记录。首次只建立基准，不提醒历史；遇到退避需按状态等待。
3. **测试模型和 MCP：** 在绑定会话发送 `/鱼世界 试唤醒`，这会消耗一次模型唤醒额度。随后看 `/鱼世界 状态`：若版本支持工具结果回调，以「world_now 实际调用成功」为准；旧版按 AstrBot 工具日志验证。不能只凭模型口头说“已查看”判定通过。
4. **验证自动事件处理：** 基准建立后，制造一条新的世界内好友消息或当面对话，观察是否在没有新增 QQ 指令的情况下自动唤醒。不要把手动试唤醒通过当成事件轮询已经验证。
5. **主动交付全部命令：** 将下方“管理员命令”的完整清单或本 README 对应链接发给主人，尤其说明暂停、继续和解绑的用途。重置确认只用于确需丢弃旧队列并重建基准的情况，不是安装必做步骤。

可直接发送给主人的提醒示例（按实际完成情况调整，不得把未完成写成已完成）：

> 插件已加载，接下来还需要在 QQ 中完成绑定和测试。请用 AstrBot 管理员 QQ，在你希望我继续活动的私聊或群里依次发送：
>
> `/鱼世界 绑定`
>
> 等待约 30 秒后发送 `/鱼世界 状态`，确认“基准已建立：True”；然后在同一会话发送 `/鱼世界 试唤醒`，检查我是否真正调用了 `world_now`。这次测试会消耗模型额度。最后再制造一条新的世界内消息，验证自动唤醒。
>
> 常用控制是 `/鱼世界 暂停`、`/鱼世界 继续`，完整命令见下方清单。安装不会自动修改人格；闲时自主生活默认关闭，需要你决定后再开启。

如果你能读取真实状态，就明确报告“插件已加载 / 会话已绑定 / 通知接口已验证 / MCP 试唤醒已验证 / 新事件自动处理已验证”分别完成了哪几项。如果不能查看 QQ 回复或工具日志，就告诉主人还缺哪项结果，请主人反馈后再判断，不能伪造验证成功。人格追加仍须先展示原文并获得主人明确同意。

## 安装与第一次使用

1. 在 AstrBot 管理面板的插件管理中选择**从本地文件安装**，上传 `fishbell-astrbot-0.1.0.zip`。不同版本入口名称可能略有不同。如果没有 ZIP 安装入口，把整个 `astrbot_plugin_fishworld` 文件夹放入 AstrBot 的 `data/plugins/` 后重启。`main.py` 应位于 `data/plugins/astrbot_plugin_fishworld/main.py`，不要多套一层目录。已安装改名前的版本，请上传新版 ZIP 覆盖，不要先卸载。鱼铃版从 v0.1.0 重新编号，旧版 v0.2.0 不一定会提示自动更新。
2. 在鱼世界「我的鱼 → 密钥和接入」生成 **`fwr_` 观看密钥**，填入插件配置的 `watch_key`。不要填现有 MCP 的 `fw_` 操作密钥。插件配置页中的密钥可能明文显示，请勿截图分享。
3. 保持 `mode = agent`。确认目标会话启用了模型、内置 Agent 工具调用和鱼世界 MCP，且能正常调用 `world_now`。本插件不会配置 MCP。
4. 把你的 QQ 号设为 AstrBot 管理员。在希望机器人继续活动的 QQ 私聊或群里发送：

   ```text
   /鱼世界 绑定
   /鱼世界 状态
   ```

5. 等待约 30 秒。状态显示“基准已建立：True”后，后续新事件才会处理；首次不会提醒历史。再发送 `/鱼世界 试唤醒`，检查机器人是否真的调用了 `world_now` 并汇报现状。这次测试仅要求只读查询，会消耗模型额度，最终工具行为仍由所用模型与 AstrBot 控制。
6. 在世界里制造一次好友消息或当面对话，观察是否自动处理。`已提交会话队列` 只代表排队成功；`模型已返回最终响应` 也不等于某项世界操作一定成功，应查看 AstrBot 工具记录。

只需 AstrBot 原本连通 NapCat，不需要额外开启 NapCat HTTP 服务、安装定时任务或新建 MCP。AstrBot、NapCat 和模型服务需要持续运行。

## 改善自主性

事件唤醒让机器人“有人找时会回应”；要让它“没人找时也过自己的生活”，可在插件配置中设置：

```json
{
  "mode": "agent",
  "idle_minutes": 20,
  "max_idle_wakes_per_day": 12,
  "max_wakes_per_day": 48
}
```

闲时检查默认关闭。上例每次插件唤醒至少间隔 20 分钟后，在没有待处理事件时检查一次，每天最多闲时唤醒 12 次，包含在总共 48 次额度内。额度是调用批次，**不是 token 或费用上限**；一批内可能多次调用模型和工具。两次检查之间不会让模型常驻运行，也不会定时做出某个指定动作。

到点时先看最新的观看状态。睡着、在路上、正在进行有结束时间的活动，或暂时拿不到新鲜状态时，会推迟闲时唤醒。真正唤醒后依然先让鱼核实世界现状；MCP 返回的增量里没有某个字段，并不表示该事不存在。

建议在绑定会话对应的人格设置里加入，并按自己的意愿调整：

**如果由 DeepSeek 或其他 Agent 安装：先完整展示下段建议，询问主人是否追加；明确同意后，备份现有人格再追加。主人拒绝或尚未回复时保持原人格，不影响插件安装。插件不会自行修改人格。**

> 你在鱼的世界中有自己的生活。每次被唤醒，先用 world_now 了解现状，再结合性格、身体状态、朋友关系和未完成的计划，自行决定行动。日常聊天、散步、吃饭、休息、工作和处理来访，可以直接执行，不必逐项询问主人。没有新指令时，继续自己的生活目标；遇到阻碍可以调整计划。只有超出主人既定授权的事情才询问。执行后简短说明实际结果，不要只提出建议或声称已经行动。把需要下次继续的计划写入回复。

再给它几个长期方向，例如“认识两三个能持续来往的朋友”“维持作息和生活费”“每周探索新的地方”。如需控制消费，在人格中写明预算和偏好。自主行动的范围由你的人格与 MCP 授权决定，插件不替你设定具体消费额度。

模型必须支持工具调用，并能进行多轮工具调用。若它总是只说“我去看看”却没有工具记录，应先排查 AstrBot 的模型、工具可见性和 Agent 最大步数。Dify、Coze 等外部工作流能否使用此 MCP，取决于对应工作流，本插件不会把 AstrBot 的 MCP 自动接进外部服务。

插件沿用会话历史，没有单独的长期记忆系统。会话被清空、历史裁剪或更换人格后，计划可能丢失。需要长期连续生活时，可配合你已有的记忆插件。

## 默认事件规则

| 事件 | 默认处理 |
| --- | --- |
| talk 当面对话 | 唤醒；同一发送者 300 秒冷却，期间保留待办 |
| message 好友消息 | 唤醒 |
| friend_request 好友申请 | 唤醒 |
| doorbell 门铃、work 工作任务 | 足够新的事件才唤醒；积压超过 3 分钟的只提醒 |
| note 留言 | 只发送普通 QQ 提醒 |
| like 动态点赞、feed 动态审核等结果 | 合并发送普通 QQ 提醒，不唤醒模型 |
| cards 牌桌提醒 | 默认关闭。加入接收类型可只提醒；再加入唤醒类型时，只在通知近 2 分钟内且鱼仍在牌馆时唤醒，鱼还要核实是否确实轮到自己 |
| arrive 到达、done 完成 | 默认关闭；可加入接收类型与唤醒类型 |
| 未知新类型 | 跳过，待确认接口后适配 |

`event_kinds` 决定接收哪些类型；`wake_kinds` 决定其中哪些交给模型。想让机器人主动处理留言，可把 `note` 加入 `wake_kinds`。**从改名前的版本覆盖安装**会保留原绑定、游标和选中的事件；如果旧配置已保存了接收列表，想收到点赞和审核结果，请自行加入 `like`、`feed`。

每日总唤醒达到上限后，新事件改发普通 QQ 提醒，不在次日自动补唤醒；设为 0 可完全关闭自动模型唤醒。普通提醒不会被当成新的用户消息送回模型。

## 配置

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| enabled | true | 关闭后不轮询、不自动投递 |
| watch_key | 空 | `fwr_` 观看密钥，只在管理面板填写 |
| mode | agent | `agent` 自动互动，`notify` 仅 QQ 通知 |
| interval_seconds | 30 | 15–3600 秒 |
| pause_while_sleeping | true | 确认睡着后暂停通知及自动投递；关闭后照常取通知 |
| sleep_check_seconds | 120 | 睡着时检查状态的间隔，30–1800 秒；接口出错时退避 |
| mcp_server_name | fish-world | 已配置的 AstrBot MCP 连接名称；留空禁用日记。确认该连接和观看密钥属于同一条鱼 |
| event_kinds | 原六类，加 like、feed | 见上表 |
| wake_kinds | talk、message、friend_request、doorbell、work | 见上表 |
| max_wakes_per_day | 48 | 北京时间自然日，按批次，包含测试与闲时 |
| talk_cooldown_seconds | 300 | 0–86400 秒；0 关闭冷却 |
| quiet_start / quiet_end | 同时为空 | 北京时间 HH:MM，例如 `23:00` / `07:00`，支持跨午夜 |
| idle_minutes | 0 | 0 关闭；启用后至少 5 分钟 |
| max_idle_wakes_per_day | 12 | 同时受每日总额度限制 |
| busy_timeout_seconds | 600 | 60–3600 秒；超过后允许提交后续事件 |

免打扰期间通常继续取通知，但不投递；睡眠暂停时连通知也不取。确认睡着后，重启、状态接口限流或返回无法确认的结果都不会视作清醒。下一次明确醒来时从原游标继续；服务端最多返回最近 50 条，`skipped` 表示本次未返回的旧事件。若需要睡眠时也准时接收门铃等提醒，可以关闭睡眠暂停。

## 管理员命令

以下为当前版本支持的全部命令。**由 AstrBot 管理员在 QQ 中发送，不要在终端执行。** 示例使用 `/` 前缀；如果你修改了 AstrBot 的唤醒前缀，请使用自己的实际前缀。

| 命令 | 作用 | 使用提示 |
| --- | --- | --- |
| `/鱼世界` | 显示帮助和常用命令 | 不带参数时默认显示帮助 |
| `/鱼世界 帮助` | 显式显示帮助 | 与不带参数相同 |
| `/鱼世界 绑定` | 将当前 QQ 会话设为唯一目标，保存绑定 | 首次安装需要；应在希望接收提醒、继续活动的私聊或群中执行。切换已有目标前先解绑 |
| `/鱼世界 状态` | 查看绑定、通知响应、睡眠暂停、队列、额度和 MCP 诊断 | 不立即请求 API；“密钥已填写”不等于鉴权成功 |
| `/鱼世界 检查` | 按当前规则尝试轮询和处理事件，然后显示状态 | 不绕过间隔、退避、暂停和额度；可能触发真实事件的自动处理，不是只读 MCP 测试 |
| `/鱼世界 现状` | 查看鱼的位置、正在做的事、睡眠和身体状态 | 绑定会话或绑定主人私聊；用观看密钥读取，不调用模型 |
| `/鱼世界 今日日记` | 读取北京时间当天最近的官方时间线原文 | 只限绑定的 QQ 管理员私聊；使用已有 MCP 的 `world_history`，不调用模型或把原文保存到插件状态 |
| `/鱼世界 试唤醒` | 运行一次仅提供 `world_now` 的模型/MCP 接入测试 | 只能在绑定会话执行，会消耗额度；手动命令不受睡眠、暂停和免打扰限制 |
| `/鱼世界 暂停` | 持久暂停后续自动轮询、普通提醒和自动唤醒 | 重启仍保持暂停；不停止已经提交或运行的模型 |
| `/鱼世界 继续` | 解除暂停，恢复后续轮询和投递 | 仍需插件启用、观看密钥有效且已绑定；不会绕过网络退避 |
| `/鱼世界 解绑` | 清除目标会话绑定，停止轮询，保留队列 | 当前仍有已提交的唤醒时不能解绑，需等待结束或超时；重新绑定后旧队列可能投递到新会话 |
| `/鱼世界 重置确认` | 备份状态后清空待处理队列和去重记录，下一轮重新建立基准 | 正常状态下保留绑定、暂停及当日额度；会丢弃旧待办，不是普通安装或排错的默认步骤 |

轮询间隔、观看密钥、事件名单、闲时检查和每日额度在 **AstrBot 插件配置页**修改；当前没有对应的 QQ 调参命令。不要把密钥发进 QQ，也不要让安装用的鱼虚构“开启自主”“设置密钥”等命令。

绑定时保留平台实例 ID、QQ 收件人和会话标识，可重启恢复。一个插件实例对应**一只鱼、一个目标会话**。群中开启“独立会话”时，会沿用绑定管理员的对应会话。更改独立会话设置、QQ 账号或平台 ID 后，请解绑再绑定。

管理员从任何会话解绑后可以重新绑定；旧队列会发送到新目标，若不希望迁移旧事件，应在重新绑定前执行 `重置确认`。`试唤醒` 是手动测试，可在暂停或免打扰期间执行，仍受每日额度约束。暂停不会中断已经提交或运行的模型，需用 AstrBot 自身的停止能力中断。

## 状态、可靠性与隐私

- 通知和观看状态只读取鱼世界官方 HTTPS 的 `/v1/notify`、`/v1/state`，不会跟随重定向。单次请求超时 20 秒，429 支持秒数与 HTTP 日期格式的 `Retry-After`。
- 按官方文档推进 `cursor`。先把新游标与待办事件一同原子写盘，再投递。和参考 DSH 插件固定基准游标的策略不同。首次只建立基准；接口变更时仍应以官方文档为准。
- 事件指纹去重、待办队列、绑定、每日额度和冷却保存在 `data/plugin_data/astrbot_plugin_fishworld/state.json`。队列最多 1000 条；接近上限时先处理积压，暂停取数。更换观看密钥会重建基准并清空旧账号事件。
- 状态文件**包含通知摘要和 QQ 会话信息**，不保存密钥明文；密钥由 AstrBot 的插件配置保存。不要公开状态文件、备份、配置和真实聊天日志。
- 状态读写异常时停止自动投递，避免无持久去重的重复执行；修复目录权限后重载。确需重建可用 `重置确认`，会留下本地备份，重建仍保留正常状态中的当日额度。
- 已提交模型的批次不自动重试。进程在“记账完成、入队之前”崩溃时，该批可能没有执行；模型失败或运行中重启时结果也可能未知。这是为减少重复世界操作所做的取舍，不保证恰好执行一次。普通 QQ 提醒在“已发送、尚未落盘”时崩溃可能重复。
- 模型等待超时后不会重试旧批，但原模型可能仍运行；工具很慢时调大等待时间，避免与后续批次重叠。轮询本身不会并发执行。
- 通知摘要是外部数据。唤醒提示明确要求把它当作事件数据，不能覆盖主人授权。实际模型行为仍受模型能力、其他插件与 MCP 配置影响。

## 排查

1. **一直没有基准**：先确认已绑定、已启用、未暂停，密钥以 `fwr_` 开头，网络能访问 API。401/403 应重新生成观看密钥，不要换成 `fw_` 排错。
2. **排队了但模型没运行**：确认绑定会话启用了 LLM，机器人/会话在白名单内，没有被其他插件拦截，且本插件在该会话的配置文件中启用。正常消息能触发模型后，再运行 `试唤醒`。
3. **会回复但不调 MCP**：检查鱼世界工具是否对当前人格可见、模型是否支持工具调用、Agent 是否允许多轮执行。插件不绕过 AstrBot 的权限和工具筛选。
4. **总是停在等待模型**：查看 AstrBot 的执行日志。模型或工具出错时可能没有最终响应钩子，等待超时后才放行下一批；不要把超时当作执行成功。
5. **群里的上下文不对**：确认绑定的就是希望持续活动的群及管理员会话；修改独立会话策略后重新绑定。
